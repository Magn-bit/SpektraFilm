# Windows 0.8.4

本次集中调整首次预览的准备路径，继承 0.8.3 的图标与工具发现修复。Android 保持 0.5.0 / code 23。

## 实际改动

- 快速与精细预览共享带源文件身份的在途解码和光学准备。代理规范化到配置的预览尺度，原尺寸请求保留独立身份；失败释放等待者，源文件变更使缓存失效。
- 镜头元数据和资料匹配在独立、单并发队列准备，与 RAW 解码重叠；过期排队请求跳过，关闭时等待清理。
- 镜头身份索引保留已解析的头部，逐文件核对路径、修改时间和尺寸；实际校正仍读取匹配的本地资料，不随包复制厂商配置。
- 库、预设、设置、同步、导出、配方和排版按首次访问创建，保留原父级及关闭后状态。基础、颜色和几何分组也按访问创建。
- 有界预览减少 GPU 往返，大图维持分块与原精度输出。提前初始化 GPU 的试验没有获得稳定端到端收益，已撤回。
- 工作区增加独立的画布、浮起工具表面与底部操作区，保留认可的字体；深色表面改为中性炭灰，避免大面积绿灰。照片栏中央小三角收起后仍可恢复，左上角月亮／太阳图标可切换并记忆浅深色。

## 关键节点

`tests.test_native_preview_controller` 与 `tests.test_lens` 共 26 项通过，包含在途共享、全源与代理隔离、源变更、缓存头部复用和资料变更失效。1366×768 逻辑尺寸下，五个工具分组和七个次级窗口首开、重开、尺寸、模态状态和对象复用通过，QML 消息 0；初次验收脚本缺少应用标识的警告已在脚本中修正，正式入口本来就设置了标识。

首次性能候选已通过版本、真实 RAW、原生大小图标与工具发现检查。该候选的两次有界检查如下（阶段数字从 Python 入口计时，整链从外部启动计时；最终含界面／材质的包单列在末节）：

| 路径 | 窗口首帧 | 首个预览 | 精细就绪 | 截图完成并退出 |
| --- | --- | --- | --- | --- |
| 现有应用缓存 | 2.107 s | 4.379 s | 4.461 s | 6.421 s |
| 新建应用缓存 | 1.699 s | 3.926 s | 3.999 s | 5.860 s |

新建路径使用独立的源缓存与镜头索引目录；系统文件、驱动和 Qt 缓存未清除，不能称为全冷启动，也不据此计算严格的冷启动加速比。测试先后次序及系统缓存会影响结果。详细记录位于发布目录 `Evidence/Windows-0.8.4/startup-resources.json` 与 `first-app-cache/startup-resources.json`。图像计算与输出语义未改，复用 0.8.2 已有的相关成品证据，不重复全尺寸导出和哈希检查。

0.8.3 的 9.25 秒是启动至完成截图并退出的整链测量，包含截图等待与 PNG 保存，不能视为 RAW 解码时间。所有性能结果仅对应当前工作站与 `DSC09118.ARW` 样片，不泛化为全部硬件和相机。

## 界面收尾

使用指定 RAW，在 1366×768 与 1440×900 逻辑尺寸检查展开／收起／恢复、鼠标与 Space 键操作、工具区独立隐藏、浅深色切换及滚动区可达性，QML 消息 0。小三角位于照片栏上沿正中，不占缩放操作组；主题切换位于左上角标题栏。仅工作区和少量操作区域使用表面抬升，没有给每个参数增加卡片。

加入工作区层次后的中间候选检查为首帧 2.186 s、首次预览 4.486 s、精细就绪 4.572 s、截图退出整链 6.484 s，原生大小图标、真实 RAW 与工具发现通过。后续继续添加统一三角入口、去重和片边材质，最终成品检查单列在末节。原始记录随 `Evidence/Windows-0.8.4` 保留。

## 片边与排版

2026-11-12 再次核对 SpektraLab 官方 main 与最新 2.3.2，仍为提交 `1952c63537ec576d24422f1065b12495631346a5`，没有新增边框式样。现有十种片幅、片门、片夹与日期后背继续保留，不以重复样式充当新增功能。

补齐八款扩展胶片的型号回退，避免统一显示“FILM”；既有实测边字与 DX 映射不改，也不编造扩展型号的 DX。排版分类跟随实际样式同步，物理片边样式改为两列较大缩略图，固定输出区与工具滚动区域分开。

`scripts/verify_frame_stock_sync.py` 检查全部 30 款材料均有型号，并对 Portra 400、Vision3 500T（EASTMAN 5219）、Velvia 50 实际运行原生预览和小尺寸 16 位 TIFF 输出，确认两条路径收到相同型号，源文件尺寸与修改时间不变。在 1366×768 和 1440×900 检查真实页面，QML 消息 0；这是型号／布局专项，未穷举全部材料的像素外观，也不是大 RAW 性能测试。

## 最终片边与发布包

片边材质在原生扫描末端处理，仅作用照片外的片基。细纹使用胶片毫米坐标与固定 seed，随像素覆盖抑制过细频率；透光颜色沿用当前材料的谱片基。按反馈进一步压黑底色，大幅减弱大面积棕色雾感与斑驳，把透光收在薄边和孔缘。不叠加随机灰尘或刻意划痕；这是程序化材质，不是实拍扫描贴图。

`scripts/verify_rebate_material.py` 使用现有样片代理，对 Portra 400 的 135／120 6×6 和 5219 的 135 做一次保护节点：照片内部像素与修改前逐项相等，同 seed 复算相等，有界预览／输出最大差值 0。曾试验边字预曝光变化，保护检查发现其影响全图归一化后已撤回；最终仅保留扫描末端局部处理。该节点不替代大 RAW 全尺寸性能测试。

最终包同步当前 QML、三角／主题 SVG、原生 DLL 与扫描 shader 后，确切 EXE 的 RAW／大小图标专项通过：首帧 2.590 s、首个预览 4.996 s、精细就绪 5.088 s，截图完成并退出 7.031 s。这是一次成品检查，不能把前述候选的最低值当作最终包保证；没有清除操作系统／驱动缓存。

打包 QML／资源另用现有代理运行 1366×768、1440×900 界面节点，确认工具区与照片栏宽扁三角可双向点击／键盘恢复、浅深色切换可用，且已加载状态仅保留顶部导入，底部重复“添加”已删除。QML 消息 0。界面节点使用相同源码控制器，确切冻结 Python 入口由上述 EXE／RAW 专项覆盖。证据分别为 `final-package/startup-resources.json`、`final-ui/review.json`、`rebate-material.json` 与 `frame-stock-sync.json`。
