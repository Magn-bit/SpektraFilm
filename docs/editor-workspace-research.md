# 编辑工作区：布局与缩放

2026-11-08。本次沿用 Qt Quick；研究对象为 SpektraLab 当前公开指南与 SwiftUI 源码。以下是公开实现分析，不将它描述为已还原 Lightroom／Capture One 私有算法。

## 证据

- [SpektraLab 使用指南](https://spektralab.app/user_guide/zh/)：照片工作区承担预览、编辑、裁切、输出；不能把全部工具当成一页阅读内容。
- [EditorWindow.swift](https://github.com/JamesQiu2005/SpektraLab/blob/main/modern_UI/Spektrafilm/Spektrafilm/Windows/EditorWindow.swift)：画布、两侧工具区和底部胶片条分工；面板可收起、拖动改变宽度；恢复入口在面板收起后仍可见。
- [PanelResize.swift](https://github.com/JamesQiu2005/SpektraLab/blob/main/modern_UI/Spektrafilm/Spektrafilm/Controls/PanelResize.swift)：视觉分隔线与 6 pt 拖动命中区分离；宽度从本次按下时的初始值计算、限制上下界，双击恢复标准宽度。
- [RightPanel.swift](https://github.com/JamesQiu2005/SpektraLab/blob/main/modern_UI/Spektrafilm/Spektrafilm/Panels/RightPanel.swift)：显影前／后的任务页切换只改变工具可见性，不丢弃文档参数；复杂工具分区不要求同时展开。
- [ViewportState.swift](https://github.com/JamesQiu2005/SpektraLab/blob/main/modern_UI/Spektrafilm/Spektrafilm/Canvas/ViewportState.swift)：100% 表示源像素对应设备像素；缩放锚定光标下的图像坐标；小于视口时居中、大于视口时限制边缘；调整面板／视口尺寸时保持原图中心坐标；裁切与图像共享原图归一化坐标。

Adobe／Capture One 的官方帮助页本次 HTTP 请求返回 403，未据其未读取内容作具体实现结论。与其私有引擎的算法等价性不在本次 UI 证据范围内。

## SpektraFilm 的选择

1. 使用“原片、基础、颜色、局部、胶片、几何”任务导航，照片与工具始终并列。仅当前任务占据参数区；曲线、HSL、原色校准、色轮按需展开。
2. 工具区宽度 320–480 逻辑像素，保留画布的最小空间；边界拖动直接响应，无追赶动画。工具区和照片条可分别收起；Tab、Z 和 Ctrl+0/1/2 提供快速查看。
3. 裁切直接出现在主预览。比例、交换横竖、尺寸、恢复、取消与应用位于画面外的上下文工具条；四角、四边、内部有各自命中和鼠标形状，支持 XPan。取消恢复进入前视图。
4. 适合窗口与像素缩放具有不同语义。100% 不以低分辨率预览的尺寸计算；更换细节纹理时不移动图像；面板调整保持查看中心，预览近似不改变导出尺寸。
5. 保留既有朱雀仿宋／Noto Serif SC 搭配、QtRendering 与纵向 hinting；不通过更换已认可字体解决信息过载。正文 15、辅助 14，以空间、选中填充与字重建立层级。
6. 连续输入由一个指针处理路径负责。滑块的拖动、双击复位、精确数字输入和键盘细调共享参数提交；一次拖动只形成一步撤销。拖动期间直接更新位置，耗时显影异步完成。

设置入口位于顶栏的低权重矢量图标。`desktop/preferences.py` 持久化有界预览尺寸、预览缓存、磁盘缓存、界面缩放及诊断保留天数；临时文件写完再原子替换。可显式导出本地诊断 ZIP，归档器只接收白名单设置和数字计时，不读取照片、源文件夹或任意日志。模块已检查边界、非法值、持久化重读和 ZIP 内容；`settings-1366x768.png` 为实际弹层截图，绑定及设置更新检查通过。

照片条的单一“同步”入口打开分类选择，复制、粘贴和批量同步共用一组明确的分类。胶片、相纸、曝光、白平衡、基础、色彩默认启用；蒙版和裁切／几何默认排除，以免复制构图破坏各张取景。撤销由既有逐图历史负责。

`secondary-verification.json` 记录真实两图同步、第二张撤销恢复，以及 PNG16 / Display P3 原尺寸配方保存成功。`sync-1366x768.png`、`recipe-1366x768.png`、`export-1366x768.png` 为该节点实际截图，QML 错误 0、进程正常退出。此次验证不把配方保存当作所有格式编码通过，编码质量由输出管线节点另行检查。

主导出仍保留高品质 JPG、分享 JPG、TIFF 与 RAW 原片四个入口；输出配方置于次级对话框。主导出／配方的操作条参与布局，内容独立滚动，最小窗口不以悬浮按钮遮挡末项。配方默认为原始像素尺寸，仅用户明确选择时缩小；JPEG8、PNG8/16、TIFF8/16、DNG16 与 RAW 依照实际管线组合限制，DNG 固定线性 sRGB，RAW 保持原片且不可缩放。

### 方向与细节

几何任务提供左／右 90° 矢量入口，采用 `quarter_turns` 独立字段。顺时针 90° 将源像素中心 `(x,y)` 映射到 `(h-1-y,x)`，完整输出画布转置为 `(h,w)`；细微旋转、透视、翻转和裁切随后在转置画布计算。纯 90° 与裁切通过索引转置完成，不重新采样、不为填满画布放大图片。源尺寸和蒙版源坐标始终保留，裁切使用单独的转置后尺寸。

一个 9×13 非对称像素 fixture 覆盖四个方向、明确裁切、PIL／高精度数组像素完全一致及蒙版归一化坐标往返。`quarter-turn-verification.json` 另记录真实 QML 按钮点击、撤销／重做、源坐标不变、裁切画布交换横竖与绑定错误 0；`quarter-turn-1366x768.png`、`quarter-turn-crop-1366x768.png` 已检查没有遮挡和裁切尺寸错配。该检查不重复全分辨率 RAW 导出。

基础任务新增可收起“细节”组，包含锐化、明度降噪和彩色降噪，三者默认 0；与既有纹理／清晰度／去雾的“质感”分组区分。控件沿用首按即拖、精确输入、双击复位和单步撤销。

### 蒙版、色阶与全图直方图

局部参数开始一次指针或键盘编辑时，画布只隐藏选区叠加而保留已经生成的蒙版位图；编辑结束后立即恢复同一源图，不重新遍历笔迹。这样调整曝光、色温或对比度时不会被红/青色覆盖层干扰，也不会因为显示开关变化而产生新的覆盖层版本。

蒙版填色使用后台生成的 RGBA 图层，与最终 `rasterize_mask` 共享柔边、流量、擦除、反相和几何坐标。QML 只合成该位图，局部曝光等调整不重建历史笔迹。源坐标控制器单独绘制双描边轮廓、羽化范围与控制点；拖动时使用本地草稿即时跟随，以 16ms 合并提交并在松手时提交最后值。画笔光标仅绘制局部小画布，笔迹不在指针事件中重放；叠加支持红／青与独立显示浓度。

基础任务的“色阶”包含 RGB／红／绿／蓝四通道、256 桶直方图、黑场／中间调／白场三个输入柄和两个输出柄。中间调位置按 `black + (white-black) * 0.5^gamma` 表达；输入端点不交叉，输出端点可交叉反相。精确输入显示 0–255 和 gamma 三位小数，后端保留归一化浮点；双击单柄恢复默认，一次拖动只形成一步撤销。此处借鉴色阶工具的交互语义，不声称移植专有算法。

全图 RGB 与亮度直方图置于任务导航下、参数滚动区外，约 92 逻辑像素，可独立收起。悬停区间统计由指针项计算，画布只随数据／尺寸重绘。白平衡、影调、色阶和自动拉直在各自任务内提供自动入口；高动态范围单独包含高光／阴影／白色／黑色，亮度与曝光独立。

`verify_mask_levels.py` 聚合真实 QTest 输入：960×640 小代理上的画笔 10 点、擦除柔边 15771 个非整值 alpha 像素、线性／径向移动、局部曝光拖柄同事件移动 30px（位置误差 0），一次历史和叠加版本不变；色阶输入黑场 0.0625、gamma 1.237、红通道黑场 0.05、撤销／重做，及四个自动按钮实际点击完成。1366×768 逻辑窗口、最窄 320px 侧栏的绿／蓝通道真实点击与全部精确输入框在可视区边界内通过，QML 错误 0。`mask-levels-verification.json` 和 `mask-linear-guide-1366x768.png`、`mask-radial-guide-1366x768.png`、`levels-input-output-1366x768.png` 为证据。该节点不从小代理推断大图性能或 60fps，也不重复全尺寸 RAW 导出。

脚本支持 `--qml-root` 指向候选包 `_internal/desktop/qml`；此模式另写 `mask-levels-packaged-verification.json` 和带 `-packaged` 后缀的截图。它验收候选 QML 资源配合开发态 Python controller／已阶段部署的原生运行时，不能替代最终 EXE 本体的启动和关键流程验收。
