# Bayer 可读参考与原 GPU 算子对照

日期：2026-11-07。本轮在隔离研究模块 `native/reference/c1_bayer_reference.py` 中，以可读 NumPy 公式实现了 CFA 初步绿色、绿色方向细化、对角色彩重建和绿色位置 R/B 重建。模块没有进入应用或发布依赖；没有把提取的专有 OpenCL 源改名放进产品。**四阶段参考级联尚未全部通过严格数值对照**，保留了可复现的失败证据，不能称为完整还原。

## 实现范围

| 参考函数 | 对照原 kernel | 输入与行为 |
| --- | --- | --- |
| `initial_green` | `zb4a41b922a` | ushort CFA；固定点方向评分、歧义重检、正则化色绿比，补初步 G，保留原 CFA |
| `refine_green` | `z13bff1d853` | 稀疏 float4 RGGB；八方向评分，只细化 R/B 位置的 G |
| `fill_opposite_chroma` | `z95ba5a4538` | 比较两条对角线的颜色变化，结合 G 和同色远邻，以正则化色绿比补 R 位 B／B 位 R |
| `fill_chroma_at_green` | `z48dd14e643`，mode 6 | 轴向四邻域、倒数变化权重及色绿比，补两个 G 位置的 R/B |

接口要求偶数 RGGB 起点、偶数尺寸；第一步需要六像素 sensor halo，其余步骤需两像素有效输入 halo，返回独立 ROI float32 结果和分支计数。没有边界扩展或隐含默认参数。第一步使用显式 `InitialGreenParameters`（R 行增益、B 行增益、正则项、参考偏置），后续使用显式 `ChromaParameters`；参数只作公式权重，不冒充黑白电平、降噪或 A7CR 标定。辅助方向图、local-memory、非 RGGB 变体直接抛出 `NotImplementedError`，没有静默套用本分支。

绿色细化使用八个候选及各自的变化评分。最小值的方向为水平／垂直时保留当前绿色；其他方向将对应候选与较优轴向候选平均。相同评分按观察到的严格比较顺序选择。颜色步骤将方向变化和色／绿相对量分别用于权重，再以带正则项的色绿比恢复缺色。代码中的命名和分支计数用于审核这些数学含义，不依赖混淆变量名。

第一阶段按明确的整数／浮点语义实现：固定点系数取 floor、除法向零截断；保留在本 NVIDIA 后端观测到的 int32 歧义平方溢出结果。方向证据先看远轴向与 3×3 同色网格，歧义时再看 5×5 网格，最终选水平、垂直或混合色绿比。发现并按原式保留了一处非对称性：水平分支的东侧变化整体乘 gain，混合分支则仅同色差乘 gain；没有为了对称美观改动数学。

实验分三种检查：各阶段使用相同输入单独比较；从原 GPU 第一阶段结果开始，级联后三段参考；从第一步开始，级联完整四段参考。三个结果分别保留，避免单段通过掩盖后续离散方向选择对浮点误差的放大。

## 实际验证

`tests/test_recovered_bayer_reference.py` 在 NVIDIA RTX 3070 Ti Laptop GPU / OpenCL 3.0、PyOpenCL 2026.1.4 上直接编译本机提取的原始源作为 oracle。使用 `-Dzbc6516e8d5=0 -Dz3dbd1ff682=6`；每个源 SHA256 和设备驱动见 `output/captureone-bayer-reference/report.json`。

19 个场景、76 个单段比较均通过既定 float32 容差；从同一 GPU 第一阶段开始的 19 个后三段级联通过。完整四段级联有 3 个场景未通过原严格容差，详见下节：

- 9 种 128×96 场景：黑场、不同 RGB 平场、65535 白场、横边、竖边、斜边、局部 65535 高光、独立通道随机场、平滑斜坡。
- 人工后续权重 `(1,1,1,1)` 和 `(.65,1.2,16,2)`，不是 C1 或相机默认值。第一阶段分别用 `(gainR=1,gainB=1,regularizer=1,bias=0)` 和 `(.75,1.25,16,512)`，禁用辅助方向图。
- 一张 A7CR 的实际 512×512 传感器裁片，只用 rawpy unpack，未应用黑电平扣除、WB、矩阵或显示曲线。sensor 裁片起点 `(4526,2932)`，RGGB，pattern `[[0,1],[3,2]]`、color_desc `RGBG`；最终有效区 464×464。原片前后 SHA256 相同：`c0d80fc67e79e84ee5c4d6ba71c11c8407af13356f47ac2fec53176b73cae56e`。

误差按未归一化传感器幅度报告，float32：

| 对照 | 全部场景最大绝对误差 | 实际 A7CR 裁片最大绝对误差 |
| --- | ---: | ---: |
| 第一阶段初步绿色，单段 | 0.01953125 | 0.0002441406 |
| 绿色细化 | 0（逐像素一致） | 0 |
| 对角缺色重建 | 0.03125 | 0.0001831055 |
| G 位置缺色重建 | 0.03125 | 0.0003051758 |
| 后三段参考级联（同一 GPU 初步绿色） | 0.03125 | 0.0002441406 |
| 完整四段参考级联 | **1703.4765625，严格对照失败** | 0.0004272461 |

单段 0.03125 相当于约 4.77e-7 的 65535 满量程。OpenCL 的浮点乘加收缩与 NumPy 分步 float32 运算会产生若干 ULP 差异，因此没有声称所有阶段逐位相同。测试同时限制绝对和相对误差，保存 max／mean／RMS。每个阶段原 CFA 采样通道均精确保留，输入不改、输出有限、GPU 目标 ROI 外 canary 不改。

第一阶段水平／垂直／混合均命中，合计 28364／19905／138195。5×5 重检 12938 次，重检后水平／垂直／混合分别 739／718／11481；歧义平方 int32 环绕 96 次。第二阶段绿色方向 0–7 全部命中；轴向保留与斜向更新均覆盖；对角两方向、适应性权重开／关以及 G 位置 R/B 两通道的权重开／关均覆盖。详细计数保存在报告中。

## 已定位、尚未消除的四段级联差异

没有提高容差把这些误差归为通过：

| 场景／第一阶段人工参数 | 第一阶段单段最大差 | 第二阶段方向改变数 | 最终四段最大差 |
| --- | ---: | ---: | ---: |
| 高光／(1,1,1,0) | 0.01171875 | 20 | 105.5501099 |
| 横边／(.75,1.25,16,512) | 0.0002441406 | 48 | 1.30078125 |
| 高光／(.75,1.25,16,512) | 0.01171875 | 359 | 1703.4765625 |

高光单位参数的 `(x52,y28)`：用 GPU 第一阶段结果计算的第二阶段评分为 `[0,0,0,105335,...]`，选方向 0；用参考第一阶段结果时前三项变为 `[0.0003662109,0.0003662109,0]`，选方向 2。这把近零平局从“保持当前 G”切换成了斜向候选平均。最终 `(x52,y68,G)` 为参考 794.4498901、原 GPU 900，差 105.5501099。

非单位参数高光的最大差位置为 `(x73,y67,G)`，参考 59703.4765625、原 GPU 58000。实际 A7CR 裁片也出现了 3 次方向改变，但本次最终差仅 0.0004272461。不能把这张实际裁片良好表现泛化为所有图像都稳定。

`report.json` 保留每个失败场景的第一阶段最大差坐标、阶段传播误差、第二阶段方向／评分 margin／8 项分数、最终最大差坐标和值。独立 `diagnose_float_contraction.py` 还比较原始默认构建、插入 `FP_CONTRACT OFF` 的诊断构建及 `-cl-opt-disable` 构建：禁用收缩令单位参数高光的四段差从 105.55 降至 0.01953，但非单位参数仍有 1206.14；仅禁优化与默认输出相同。这支持浮点计算形式会影响离散方向选择，**尚不足以把全部差异归因于某一条 FMA**，也没有将修改后的诊断编译结果冒充原 C1 默认行为。证据为 `float-contraction-diagnostic.json`。

严格四段对照以一个明确的 `expectedFailure` 保留在测试中，修复后会出现 unexpectedSuccess，要求更新已知问题；其余单段／后三段／变体拒绝测试通过。测试报告状态为“3 项通过、1 项已知失败”，不是“四阶段完全恢复”。

## 未覆盖与限制

没有恢复／验证辅助方向图、local-memory 编译变体、色差校正分支、SensorPlus、完整图像边界策略、噪声／相机标定、真实宿主调度参数或完整 RAW 显示流程。四段浮点级联仍有上述已知差异。测试 halo 均来自前一步有效区域；没有用零填充伪造边缘，也没有测试未知 padding 策略。负传感器输入和所有可能的极端浮点权重不在当前覆盖内。

本轮只能证明这些步骤在明确人工条件下的数值对应及实际 CFA 输入兼容性；不是 C1 成片等价、画质优劣或性能结论。原专有源只作为本机研究 oracle，参考实现仍为研究用途，没有生产接入。

## 新增：明确区分原生 CPU 与 OpenCL 的第一阶段

后续获得了同一已安装 C1 build 的正常 CPU 运算输入／输出，并在独立进程中调用已检查 ABI 的两个无外部调用数学 worker：分类 RVA `0x16816d0`、插值 RVA `0x1682d90`。DLL SHA256 为 `ca02b6ac2786e9a100f63221df7340e5df210416eb0bd53a4bb1bfc2306a44a4`；研究脚本只读加载本机原 DLL，先核对哈希，不启动／修改原应用或设置。

新增显式 `initial_green_cpu`，原 `initial_green` 继续保持 OpenCL 算术语义。两者共有可读公式，但以下三处按实际原生结果分开，不再把 CPU 和 GPU 差异当作简单 ULP 误差：

| 环节 | OpenCL 参考 `initial_green` | CPU 参考 `initial_green_cpu` |
| --- | --- | --- |
| 中心分类幅度 | `floor(float32(raw) * gain) + offset` | `(raw * floor(gain * 1024) >> 10) + offset` |
| 两个同色点中值 | `(center + neighbor + 1) / 2` 的整数截断 | `(center + neighbor) / 2` 的整数截断 |
| 纯水平方向的东侧变化 | 整个整数变化乘 gain | 仅同色差乘 gain，和混合方向一致 |

`output/captureone-bayer-cpu-reference/probe_cpu_reference.py` 在隔离进程对 28 个场景比较原 native scalar worker 与可读 CPU 参考：9 种合成场景 × 3 组显式参数，加上正常原应用捕获的 A7CR 64×64 ROI。合成场景包括全黑、带奇数采样值的不同 RGB 平场、65535 白场、横／竖／斜边、局部高光、独立通道随机场和奇数斜坡，64×80 输入的有效区 56×40。前两组人工参数为 `(1,1,1,0)`、`(.75,1.25,16,512)`；第三组及实际捕获使用本次观测设置 `(2.5120000839,1.6759999990,166.69566345,2048)`，**不是 A7CR 或 C1 通用默认值**。未捕获／模拟非零辅助方向差。

本次 32288 个 R/B 位置的分类全部一致，三个方向各有 4834／2075／25379 次。全部位置还强制执行了水平、垂直、混合三种插值，96864 个候选均逐 float32 一致，最终 CPU 第一阶段输出最大绝对误差为 0。实际捕获 ROI 的原 native scalar、原应用正常 CPU 输出和可读 CPU 参考三者也逐 float32 一致。原采样通道精确保留，输入未修改，输出有限。详细逐场景结果为新目录的 `report.json`。

实际 ROI 中，原 OpenCL kernel 与原 CPU 输出最大差为 230.080078125；原 OpenCL 可读参考与原 CPU 最大差为 230.078125。CPU 参考的精确对应没有修复或替换前面保存的 OpenCL 完整四段级联问题；两个结果属于不同算术路径，不能互换解释。

新独立测试 `tests/test_recovered_bayer_cpu_reference.py` 共 3 项，0.861 秒通过，其中 native oracle 验证要求最大误差和方向错数都为 0；没有靠宽松容差宣告精确通过。原 GPU 4 项回归再次运行 1.640 秒，仍为 3 通过加原有 1 项已知失败，旧数值报告与失败证据未重写。

这一结果仅覆盖本 build、显式 RGGB／辅助差为零的第一阶段 scalar worker。没有证明完整 CPU demosaic 级联、非零辅助图、其他 CFA、边界、相机色彩或完整 RAW 成片等价，没有生产接入，也不构成速度或画质结论。

