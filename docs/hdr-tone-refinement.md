## 2026-11-09：空间细节与连续预览修正

本机 Capture One 的静态研究明确区分控件和像素算法：

- `P1.C1.ViewModels.dll` 的 `ShadowHighlightViewModel` 为 Shadow、Highlight、Black、White 保留独立 slider presenter。选定类型及线性渐变类型的 CIL 成员检查覆盖完整，Evidence `ev_e73423f1e555775707af1ba77f6967ccbc641366dc69c698ec1c550b1f26789c`。本地研究记录在 `output/c1-hdr-gradient-evidence-20261109.json`，不随产品打包。
- `ImgCoreDll.dll` 内嵌 OpenCL 字符串区 `0x27a6d60` 附近有 `Luma pyramid`，`0x27ade28` 起的诊断为 `No Pyramid, skipping OpenCL HDR`；随后有 `CImgOpLocalToneMappingV8` 的参数/金字塔输入诊断。这证明其 HDR 路径存在空间亮度金字塔，不能把简单点曲线称为完整 C1 算法。真实曲线参数、金字塔搭建及完整调用链仍未恢复。

产品改为独立的边缘保持亮度基底：在 log2 线性亮度域以 9 个稀疏高斯空间采样和四次方范围权重构建基底，尺度固定为朝向后源图的 48 像素，范围阈值 0.7 EV，65% 基底分离。高光/阴影映射基底，增益同乘原 RGB，因此不模糊画面/颗粒，线性色比保持。强曝光边界拒绝跨边混合；真实黑保持黑，超白在最后显示/编码前保留。阴影/高光可用幅度扩为 3.3/4.3 EV，rolloff 为 1.7，极端灰阶组合仍单调。白/黑是更窄的端点区域，曝光 EV 和中间调亮度的语义保持分离。零值绕过基底和所有 HDR 运算。

共享 NumPy reference 和原生 Vulkan 采用相同公式。预览按胶片/曝光/WB/对比度等真实依赖缓存单通道基底，高光/阴影数值本身不使基底失效。`spk_editor_process_with_tone_base` 接收同尺寸单通道平面；正式大图不依赖整幅基底，原生 shader 在有界分带及 halo 中计算同一采样。局部蒙版仍按自己的局部亮度应用相同高光/阴影范围，未假装与 C1 金字塔逐像素等价。

预览修正还包括：640 快预览也保留完整光谱底片/源预处理缓存；缓存命中后不再重跑无关的 pre GPU 步骤；原图比较层按几何/显示配置缓存；无自定义显示器/打样时精确使用内置矩阵/TRC，省去通用 ICC 曲线评估；标准 sRGB 显示保留浮点余量并直接结束于 sRGB，避免末尾 sRGB→ProPhoto→sRGB 来回。Windows 自带 `sRGB Color Space Profile.icm` 按真实色度/TRC 识别，不能只比文件名或 bytes；其真实舍入矩阵和 1024 点曲线保留，通过编译的 C 核和 65537 点一维 ICC 曲线表进行浮点显示评估。此表仅代替 ICC transfer curve 评估，不替代任何光谱计算。与实际 LittleCMS 同源对照最大差约 0.000141，修复了直接忽略其舍入矩阵产生的 0.00267 暗部色差。带 LUT、vcgt、非零黑点或非 sRGB 色度/曲线的校准 monitor ICC，以及 soft proof/gamut warning 保留 LittleCMS。CPU 缓存统一内存预算包含新增数组。

Vulkan 同步契约保持不变，提交改为复用 command buffer/fence，并只等待本次提交，而不是每个 upload/dispatch/read 都重新分配命令并 drain 整个 queue。底片/输出/分带生命周期仍在 fence 完成后回收。

HDR 不再通过灰色偏移和逐通道裁切抬暗部、压高光，而是在线性亮度的 EV 轴上应用连续分区增益，再对 RGB 施加同一增益。保留真黑、原始超白浮点值与线性色比；高光/阴影围绕 18% 灰相接，白/黑使用更窄的支持区。零调整精确旁路，极端组合的灰阶保持单调。共享 Python 与 Vulkan 色彩/局部蒙版实现保持一致。局部曝光与 HDR 在输出裁切前处理，多个蒙版不会提前丢弃高光余量。

## 中画幅分块的额外问题

完整光谱的“高光增益”和无防光晕层材料的“高光余量”都依赖整张照片的峰值：前者在光谱重建及曝光后测量，后者在增益后测量。原先外部分块对各自的图块测量峰值，同一光亮区域会因图块计划改变而得到不同曝光，可能出现亮度跳变。编码 RGB 的最大值或预览图的最大值都不能替代这两个统计。

增加最小执行契约：`spk_solve(..., "exposure_peaks", ...)` 返回 `frame_exposure_peak` 与 `frame_boosted_peak`。有界预扫覆盖所有原始像素，进入相同的解码、宽容度、光谱重建与曝光节点；每个条带不超过 400 万像素或 512 行。增益是单调、逐通道一致的映射，因此直接在同一 GPU 节点上计算最大曝光的增益值即可获得增益后的精确峰值，不必再分配完整光谱平面。

Python 在各条带上分别取两个字段的最大值，将同一对结果发送给所有正式图块。两个字段默认 `-1`，普通单帧保留原有 GPU 归约；未开启增益或余量时完全跳过额外预扫。执行字段不进入用户编辑参数。无固定全图曝光的自动测光请求被拒绝，避免在预扫时把整图测光悄悄变成各块测光。
