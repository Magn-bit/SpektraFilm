## 2. 已确认的设计方向

保留用户认可的主体结构：大面积照片工作区 + 单侧精密参数面板 + 克制的顶部操作区 + 底部照片序列。重点是照片、胶片性格和调节操作，整体像精心设计的桌面暗房工具。

简约而不简陋：通过留白、对齐、比例、材质明度、字体与交互层级获得品质感。工作区、工具面板、主操作、辅助说明和浮层应一眼区分，但不能依靠不断增加盒子、分割线和阴影。

沿用冷白或浅中性色、石墨文字和少量鼠尾草绿强调色。强调色用于有效选择、焦点、状态与少量交互，不能大面积染色。参数说明与次要文字可以减弱，但必须清晰可读。

禁止居中营销 hero、三卡片开场、紫蓝渐变、过量玻璃拟态、emoji 图标、默认组件库外观、后台仪表盘式小卡片堆叠，以及为了填空添加的标签、口号和装饰。不要仿制苹果商标或复制整套 macOS 桌面外观。

不要加入 AI 仿真照片、生成风景、假样片或伪造的前后对比。正常启动显示精致的导入空状态，照片由用户导入。内部测试可以使用清楚标注的校准图，不能把测试图伪装成真实照片或默认内容。

## 3. 字体与信息层级

最新字体要求优先：保留当前用户认可的主体字体，在胶片名称、分区标题、空状态主文案等少量有意义的位置使用明朝体。若当前字体本身已属于明朝体系，可以通过字重、大小和间距区分角色，不为混搭而额外换字体。

字体家族原则上不超过两个，字阶不超过四级。正文、操作、参数名称和数值保持稳定一致，避免标题、按钮与数据各用一套字体。明朝体采用有合法授权、可随软件分发的真实字体，例如项目已有 Noto Serif SC，保留字体许可证。

建议沿用现有四级 token：展示 32、标题 18、正文 14、说明 12，Windows 按逻辑像素/DPI 处理，Android 使用相应 sp 层级并支持系统字体缩放。必要调整必须按角色整体修改，不能给每个控件任意字号。

参数数值对齐、单位完整、正负号明确，动态变化不能导致布局跳动。检查中英文、数字、长胶片名和缺字回退，不因字体风格牺牲按钮辨识与操作可读性。

## 4. Windows 窗口与导出区的明确要求

窗口控制使用 mac 风格三颗彩色小圆点，但按用户明确偏好放在右上角。从左到右为：黄色最小化、绿色最大化/还原、红色关闭。它们是真实窗口操作，不能只是装饰。圆点视觉克制，点击区域、键盘焦点和无障碍名称必须完整，不依靠颜色区分功能；悬停可显示清晰的功能符号或提示。

顶部可拖动，支持双击标题栏最大化/还原；按钮区域不触发拖动。保持 Windows 的 Alt+F4、任务栏、Alt+Tab、多屏、缩放和边缘调整大小行为。恢复态窗口采用连续且抗锯齿的圆角，内容、背景和边框共同裁切，四角无方形底色、黑边或漏色；最大化时贴合工作区，不留下不合理的圆角缝隙。

记住上次关闭时正常窗口的位置、尺寸和最大化状态。先读取状态，再显示窗口，避免默认位置闪现。最小化关闭后不能下次启动成不可见最小化窗口。保存正常几何与最大化状态时机正确，不把最大化尺寸覆盖正常尺寸。考虑不同 DPI、负坐标显示器、断开外接屏、任务栏工作区和异常配置；窗口始终恢复到可见且可操作的区域。

导出区是主要操作之一：有照片且处理完成时使用深色底、清晰浅色文字；没有照片、正在处理或正在导出时，用独立的禁用/忙碌设计表达状态。禁用态仍须看清“导出”文字，不通过整体降低透明度把文字一起压暗。采用浅灰底、可读深灰文字与克制边界，并说明不可用原因。不要叠加父子透明度，不用小而模糊的图标承担主要含义。

导出按钮与导入操作、窗口圆点分属不同层级，间距充足，不挤压标题或互相抢注意力。支持键盘焦点、明确的处理中反馈，导出完成和失败都有可理解反馈。

## 5. Android 对应设计

Android 与 Windows 共用颜色、字体角色、留白节奏、胶片名称和参数语义，保持同一品牌。按手机屏幕重排为照片主视图、易触达的调节区、胶片选择与导出流程，不把桌面侧栏等比例缩小。

遵循系统安全区、状态栏、导航栏、返回手势与权限流程；触控目标通常不小于 48dp，支持字体缩放、TalkBack 和设备旋转。桌面三圆点只用于 Windows，手机不放虚假的桌面窗口按钮。使用系统文件选择/照片选择与真实保存流程，错误可恢复，不滥要权限。

图像操作不能阻塞主线程。处理旋转方向、大图内存、后台切换、取消和过期任务；明确手机端与 Windows 端的处理能力差异，未实现 RAW 或完整光谱模拟时不能标注为支持。

## 6. 动效规范

建立共享 motion token：例如 fast 140ms、standard 240ms、panel 360ms、page 480ms，以及统一的缓动或符合所选引擎惯例的弹簧参数。单段不超过 500ms，页面级不超过 600ms，入场位移不超过 16px，同屏并发不超过四个，交错间隔 40–60ms。

覆盖 hover、focus-visible/键盘焦点、pressed、disabled、loading、empty、error、胶片选择、面板开合、对比与页面转场。动效可中断、可逆，快速连续操作不堆积队列，不误发布旧渲染结果。

优先仅动画 transform/opacity 及原生等价属性。先确定稳定布局，再使用平移、缩放与透明度表达变化；禁止用淡入淡出遮盖布局跳变，禁止为动效引发整页重排或重绘。阴影变化优先在静态层之间通过透明度交叉过渡，与表面抬升同步。

读取系统减少动态效果偏好，并提供可控的应用内选项。减少动态时保留状态与操作反馈，去掉不必要的位移与缩放。目标是稳定流畅的 60fps；只有实测才能声称达到，注明测试设备、场景和限制。

## 7. 阴影与材质规范

建立 e0–e4 阴影 token，统一光源方向，组合环境光、主光和接触影。e0 用于平面工作区，e1 用于有限的可交互表面，e2 用于照片或轻量浮起对象，e3 用于浮层，e4 用于最高层对话框；具体使用须符合当前结构，不要求每个层级都同时出现。

阴影仅表达层级和可交互性。普通文字、标签、每根滑杆和所有容器不应各自带阴影。抬升与阴影同步，有明确接触关系，避免悬浮贴纸感和脏灰边缘。

深色模式若实现，应通过表面明度、边界与内高光重建层级，不能只把浅色阴影涂黑。没有完成深色视觉与截图验证时，不宣称已完整支持深色模式。

## 8. 引擎与架构决策

已有项目沿用已确定架构：Windows 采用 Qt Quick/QML + Python 图像科学内核；Android 采用原生 Kotlin，照片交互可以使用 Canvas/专用渲染视图。不得为了追逐热门框架或统一代码量随意重写。

在继续主要实现前，提供或更新选型记录和至少三个候选的决策矩阵。比较 Qt Quick/QML、WinUI 3、Flutter、React + Electron 等，维度必须含：交付形态、原生窗口控制、动效原语、图像管线整合、启动时延、实际安装体积、内存、SSR/水合适用性、无障碍、维护与打包成本。原生应用的 SSR/水合明确标注不适用，不编造优劣。

解释为何选择最适合本项目的方案，以及为何不选最流行的候选；禁止以“大家都用”为理由。未知性能数据标为待测，测量方法与数值分开。QML 按其原生声明式动效与状态方式实现，不套用 Web 框架的动画模式。Android 同样遵循本平台惯用交互。

图像科学内核、工作任务调度、文件导入导出、项目状态和界面分层清晰。参数设置只负责描述处理意图，渲染由可取消或可丢弃过期结果的后台任务执行。预览与全尺寸输出共享明确的参数和色彩语义，不能 UI 显示一套、导出使用另一套。

## 9. 胶片处理与真实功能

优先研究原仓库的胶片配置、显影流程、相纸、扫描、色彩管理与许可，复用真实科学数据，不把任意手调滤镜宣传成原版光谱模拟。

可将原版科学管线离线生成的 3D LUT 用于轻量预览，但必须记录输入/输出色域与传递函数、LUT 尺寸、通道与轴顺序、插值、负片/相纸和反转片处理约定。若颗粒、光晕或暗角采用近似算法，清楚说明近似，不声称与完整管线等价。

核心流程包含：真实文件导入、胶片选择、参数调整、原图对比、适合/100% 查看、可用的撤销重做、每张照片状态、真实导出和清晰错误反馈。按平台能力实现曝光、对比、色温、饱和、颗粒、光晕、暗角与混合；未完成的能力不能展示成已可用。

明确支持的输入格式、RAW 能力、EXIF 方向、色彩空间、输出格式、位深与尺寸。8bit 输出不能写成 16bit；sRGB 输出不能宣传软打样。保留原片，拒绝意外覆盖，输出失败不残留看似成功的文件。

预览合并高频更新，后台计算期间界面可操作，旧任务不得覆盖新选择。全尺寸处理控制峰值内存，必要时分块与使用 float32；不能把一次缩略图速度当成全分辨率性能。

## 10. 图片生成与密钥

当前设计不需要生成照片，默认不调用生图服务。不为满足工具使用而生成素材。优先通过排版、真实控件与简洁矢量图标完成界面。

若确实需要并且用户授权生成非照片装饰素材，用户指定服务为 https://image.hapiopen.cc/，模型名称为 gpt-image-2.5-sunburst，使用服务实际支持的最高质量。每次只请求一张，串行执行，不批量并发。先核实该服务真实端点和参数，不假定与其他 API 完全相同；不可用时如实说明，不静默切换模型。

所有 API 密钥仅从安全的环境变量或系统凭据读取，例如 IMAGE_API_KEY。不要把用户曾提供的密钥复述进提示词、源码、日志、截图、仓库或构建产物。不要生成官方标志、假产品截图或伪造真实处理结果。

## 12. 必须核对的验收项

视觉：空状态、已导入照片、胶片选择浮层、导出可用/不可用/处理中/失败；在相同尺寸与 DPI 下核对真实截图。导出文字清楚，右上角三圆点对齐，所有边角裁切正确，长文字与小窗口不溢出。Android 必须单独截图或明确注明未取得运行截图。

窗口：三圆点真实动作、标题栏拖动/双击、各边角缩放、普通关闭后恢复位置大小、最大化关闭恢复、最小化关闭、不同 DPI/多屏断开与异常设置回退。

图像：验证 LUT 轴顺序与插值、参数零值/混合零的语义、原图不变、EXIF 方向、导出尺寸/格式/色彩配置和不覆盖约束。完整光谱模式需要独立的小图实际运行验证。

状态与并发：每张照片独立参数、撤销重做、持久化恢复、快速切换与连续拖动下过期结果不发布，加载失败可恢复。

无障碍：键盘完成主要流程、焦点可见、合理名称、禁用语义、文本对比、系统字体缩放、减少动态效果；Android 加入 TalkBack 和触控区域检查。

性能：记录实际设备、图像尺寸、模式、冷/热启动、预览与导出耗时、内存和代表性动效帧表现。没有测量不写稳定 60fps、极速、零卡顿或生产级。

交付必须区分源码完成、构建通过、桌面运行验证、Android 真机/模拟器验证和性能实测。没有设备不等于通过手机验收，静态截图不等于功能全部通过。禁止虚构测试、兼容性、完成比例与性能结论。
