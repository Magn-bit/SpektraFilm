# Windows 蒙版交互修复 · 0.8.5

画笔在连续输入时可能一直丢弃已完成的覆盖层，直到松手才显示；光圈和渐变控制线还会逐次重绘 Canvas、上传位图。此次将交互绘制从照片显影中分开处理。

- 画笔光圈采用 Qt Quick 场景图变换，随源图几何变换定位；覆盖层仅增量更新当前笔迹。允许发布当前同一笔的已完成前缀，下一帧继续补齐，撤销、反相、擦除属性、几何和图层变化会拒绝陈旧结果。
- 线性与径向选区在 GPU 上按真实柔边公式计算。控制线使用矢量路径，控制柄保持稳定实例；较细的明暗双层线在亮部和暗部都可辨，选区颜色统一为柔和红／青。
- 画笔、渐变和局部参数仍使用原来的源坐标、最终光栅化与导出算法。此次没有改变原图尺寸、导出精度或完整光谱计算。
- 工具区固定紧凑的分组目录，随滚动标示当前位置，选择后展开目标；等待嵌套布局稳定再定位。三角放在照片与工具之间的窄缝。胶片悬停使用固定色层的透明度过渡，曲线明确标为“点曲线 / 参数曲线”。

## 关键节点证据

`scripts/verify_editor_navigation_masks.py` 使用用户授权 RAW 的 1080×720 代理，在本机 Windows、150% 显示缩放、1366×768 和 1440×900 逻辑窗口执行实际 Qt 输入。每种蒙版拖动 80 次，开启 +0.8 EV 局部曝光；同时验证擦除、单步撤销／重做、反相、导航和浅／深主题。QML 警告为零。

最后一次源环境记录：画笔、线性、径向的输入派发中位数约 0.90 / 2.38 / 2.17 ms，P95 约 5.41 / 7.51 / 8.00 ms；拖动期间画笔发布了 22 个覆盖层版本。这里测的是输入派发，不是端到端显示延迟；同一场景呈现帧间隔 P95 约 24–28 ms，不能据此宣称稳定 60 fps。

GPU 选区与最终 CPU 蒙版采样最大透明度误差：线性 0.00256、径向 0.00235；裁切、旋转、透视、翻转与四分之一转之后为 0.00231、0.00374。`tests/test_mask_overlay.py` 的增量柔边／流量／擦除与最终光栅化一致性、陈旧结果隔离两项检查通过。

最终成品使用 `--smoke-test --verify-masks <证据目录>` 在隔离设置下检查真实窗口、三种蒙版拖动、覆盖层、撤销重做和必要的新资源。该节点使用排队 Qt 指针事件，避免 QtTest 同步原生输入与 Windows 文件拖放过滤器在测试循环中阻塞。完整 RAW 导出继承未改动的 0.8.4 影像管线证据，本轮不重复大图导出或执行哈希测试。

详细源环境报告和截图保存在本地 `release/Evidence/UI-refinement-20261112`；确切发布成品的结果另存 `release/Evidence/Windows-0.8.5`，以报告中的 `frozen: true` 和 `ok: true` 为准。
