## 本产品采用的流程

服务商配置 → 用户输入修图意图 → 读取当前参数与有界预览 → 外部视觉模型提出参数补丁 → 验证类型、范围和照片版本 → 展示改动 → 应用为一次可撤销操作 → 同一引擎重新预览。继续微调时读取新预览；原尺寸导出沿用原片与现有配方。

AI 请求不附带 RAW 原文件、完整本地路径或任意本地文件。用户主动开始分析时，应用只向所选服务商发送修图意图、必要编辑参数和有界预览；API 密钥只用于请求头认证，不放入模型消息。模型不获得脚本、文件删除或自动导出能力。可以使用支持图像输入的本地兼容服务，普通离线编辑保持独立。

## 技术选择

| 候选 | 优点 | 成本／边界 | 决策 |
| --- | --- | --- | --- |
| Qt Network + 小型协议适配器 | 已随应用交付；原生异步、取消、超时与 TLS；不阻塞输入 | 自己维护三种明确的请求与响应格式 | 采用 |
| Python requests + worker | 易于调用兼容接口 | 额外依赖，取消与线程退出更复杂 | 不作为主路径 |
| 各家完整 SDK | 官方工具封装多 | 依赖、包体与版本面增大，不适合简单通用服务商表单 | 暂不采用 |

协议分为 Responses、Chat Completions 与 Anthropic Messages；模型名由用户配置，不擅自替换。地址、模型和协议独立保存；Windows 密钥使用当前用户 DPAPI 保护，界面不回读明文，记录不包含密钥。不开机自动发请求，不在失败后静默改用另一供应商。

## 验收边界

模型调用由用户主动发起；应用只发送当前照片的有界预览、修图意图和必要编辑参数。AI 不接收 RAW 原文件、完整本地路径或 API 密钥。建议需经确认，应用时成为单次可撤销调整。冻结包截图确认照片与 AI 面板可同时使用；发布验收没有使用个人密钥或请求外部模型，因此没有声称供应商连通性、模型判断或最终审美效果已通过实测。
