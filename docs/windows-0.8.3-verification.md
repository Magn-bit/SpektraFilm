# Windows 0.8.3

本次为 Windows 启动资源与产品发布修订，保留 0.8.2 的影像引擎、界面字体、参数与输出质量策略。Android 仍为 0.5.0 / code 23。

## 改动

- ExifTool 优先采用随包工具或明确配置的路径，找到后立即返回；Windows 不再为可选元数据功能扫描任意系统 PATH，避免不可达目录阻塞。开发者可通过 `SPEKTRAFILM_EXIFTOOL` 提供路径。
- 正式程序和文档采集共用应用身份、PNG/ICO 资源及原生大小窗口图标。窗口创建后显式设置 `WM_SETICON`，保留既有 AppUserModelID。
- 截图等待循环在处理事件后让出 Python GIL，避免后台 RAW、镜头配置和预览任务被测试宿主抢占。该问题属于采集脚本，不能据此宣称正式应用的解码器需要 90 秒。
- 公开源码清单补齐原型 GPU shader、独立研究参考及对应文档；主页使用项目所有者指定的 RAW 实拍示例。

## 验证口径

RAW 解码单独检查中，Sony ILCE-7CR 样片的 1080 像素预览约 1.8 秒；解码与镜头准备合计约 3.6 秒，实际匹配 `FE 20mm F1.8 G` 的本机 LCP。它不是整张原尺寸导出耗时，也不代表所有相机或设备。

原生窗口专项确认 Qt 图标有效，Windows `WM_GETICON` 的大、小图标均非空。最终安装包的启动、真实 RAW 预览和图标验收记录位于发布目录 `Evidence/Windows-0.8.3`；完整影像与输出流程复用未受影响的 [0.8.2 证据范围](windows-0.8.2-verification.md)，本轮不重跑全套 RAW、导出压力或哈希测试。

打包节点拦截过一次宿主 PATH 污染：候选多收集了不兼容的 ICU DLL，QtCore 启动失败。最终包保留新 EXE/PYZ，并复用 0.8.2 已验证且版本不变的依赖／原生运行时目录，再执行本版成品专项。原生引擎与 Qt 依赖没有更新；从源码构建仍应使用隔离 PATH 的 `scripts/build-windows.ps1`。
